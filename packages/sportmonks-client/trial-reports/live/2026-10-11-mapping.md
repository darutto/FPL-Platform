**What "compound_or_partial_name" is, concretely** (diagnostic, read off the
pairs by hand): the Sportmonks `name` is the legal name (several given names and two family
names) while its `display_name` is exactly what FPL calls the player. The registry's
`surname_birth_date` tier compares the *last* word of each name, so it
resolves a legal name only when the last word coincides; otherwise the pair has
the same birth date, the same first and family name, and no tier. The other
cases are the FPL element carrying an extra family name the provider omits, word order
reversed between the sources, and short forms.

## Second pass with the provider display name (approved 2026-10-11, #418)

**Second pass over the rows the first pass left unresolved: present the
Sportmonks `display_name` as the full-name input and run the same matcher,
with the conditions the review set:** only unresolved rows (never replaces a
pair); only tier `full_name_birth_date` with both birth dates present; the club
must agree with the crosswalk the first pass built (≥ 3 unanimous pairs, else
the club is unmapped and the row does not resolve); an FPL element a first-pass
row already holds is not taken again; reported under its own method
`display_name_birth_date`.
It adds no tier and changes no threshold; it is the choice of *which provider
field is the full name*, which the script's own docstring lists as an input
unverified until FI-9. Relaxation audit, measured on this live pool by the shipped code (shape `display_name_pass_audit`):

| Question | Result |
|---|---|
| What newly resolves | 26 rows, all through tier `full_name_birth_date` (exact normalized name **and** exact birth date) |
| Would the display name move a first-pass pair | 0 of 494 (measured every run, never applied) |
| Club guard on the 26 | 0 rejected, 0 rejected as already-taken, 0 rejected for a missing birth date. The crosswalk built from the 494 first-pass pairs maps 20 of 20 Sportmonks clubs to exactly one FPL team, unanimously; every new pair lands on the mapped club |
| Position check on the 26 | 4 differ (FPL and Sportmonks classify some wide players differently), the same disagreement the 494 first-pass pairs show at 89 / 494; position is therefore not a discriminating check, and is reported only to show it was looked at |
| Wrong resolutions | none found by name + birth date + club |
| Gate after the pass | 413 / 430 = **96.0465 %** (≥ 95 %), objective 19 `observed`; by method: full name + birth date 405, surname + birth date 87, full name unique 2, display name + birth date 26 |

17 elements with minutes remain unresolved after it: 8 compound or partial
name, 7 absent from the Sportmonks squads, 1 nickname, 1 same birth date with a
different name. They go to the manual queue (a local gitignored file with the
cause of each), for a human to resolve; nothing resolves them automatically.
The post-queue target is ≥ 99 %: 17 of 430 is 4.0 %.

Risk to weigh: the pass makes the provider's display name authoritative for the
rows it touches. A display name that is not the person's name would resolve
nothing rather than someone else, because the birth date must also agree; the
club check above found none that did.
